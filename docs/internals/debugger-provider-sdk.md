# Provider SDK internals

Design and build mechanics under the [provider SDK](../debugger/provider-sdk.md).
The package map entry is in [architecture.md](architecture.md); the debugger's
own mocks are described in [mocking.md](mocking.md).

## Design

- Generic observation records what a component does with the data it is
  given. It cannot know how to make a component act: a capture session started
  over a control service, a lease taken from a coordinator, a cache filled
  before the first record. The component's author knows. A provider is the
  author's code that drives the component during a run and describes what it
  did.
- A provider ships in the author's own module beside the components, and a
  runtime build compiles it into the worker like a component.
- Go's `plugin` package is not used: it is Linux only and needs the exact
  toolchain and dependency versions. Providers are source.
- A provider's component runs for real and unmodified; its mode is
  `dependency_mocked`. No access to the running component instance is offered:
  providers act through the component's own endpoints.
- `Provider` is a struct so new optional fields never break a provider. `Run`
  is an interface only the debugger implements, so new methods are additions.
- The debugger's own mocks (filelog, Kubernetes, the spanmetrics clock) share
  the lifecycle, settings and evidence (`mock.Session`): each is prepared,
  readied, driven and closed through the same `provider.Run`. Their factory
  hooks stay internal, and the public SDK has no Collector types.

## Module and releases

- The SDK is `collector/provider/`, a nested module with its own `go.mod`,
  package `provider`, version `provider.Version` (currently 0.1.0).
- It imports only the standard library, so it never moves a release's
  dependency set and one SDK version serves every supported release.
- The root module requires it with `replace => ./collector/provider`.
  `internal/debugger/workersrc` packs it as `collector/provider/` (its `go.mod`
  and Go files). Every runtime build requires the embedded version and replaces
  it with that copy, so the version a component module requires is never
  downloaded.
- A module requiring a later SDK version than the debugger embeds is refused
  before the build resolves, naming both versions (`checkSDK`).
- Releases are tags `collector/provider/vX.Y.Z`. The Linea release workflow
  creates the tag for `provider.Version` on the first Linea release that
  carries it, and refuses a release whose provider sources changed since that
  tag without a new `provider.Version`.
- A component module that compiles or tests its provider on its own requires
  the tag; without access it adds
  `replace github.com/lineahq/linea/collector/provider => <checkout>/collector/provider`.
  A runtime build needs neither.

## Runtime behavior

- An error or a panic in `Prepare` or a hook fails the run with "provider NAME
  (PACKAGE): ...".
- A failing `OnClose` becomes a warning "the provider failed to close: ..." on
  the declaration, since the run's evidence is already complete. A served
  endpoint nothing connected to is a warning too.
- A provider name no provider of the runtime has fails the run in the worker
  ("mocks.providers names X, which the runtime has no provider for (it has
  ...)") and is an inspection diagnostic. It is not an admission error, since
  admission does not know which runtime's providers a worker has.
- Provider code runs in the worker with the components: no network, read-only
  filesystem, the run's deadline. It gets loopback listeners and its own
  settings, never host files or the host environment.
- `Check` findings with `Settings` (a value marshalling into a JSON object) are
  offered under `mocks.providers.<Name>` as diagnostic `provider_settings`;
  anything else is not offered and the finding says so.

## Discovery, builds and reports

- `manifest.DiscoverProviders` finds, in a source's importable packages,
  `func DebuggerProvider()` returning the SDK's `Provider` (by import path, any
  alias). The name is read statically from the returned composite literal (a
  string literal or constant); otherwise it is unknown until the worker starts.
- The build writes `internal/debugger/registry/providers.go`
  (`registry.Providers`), generated by `internal/debugger/registry/gen
  -providers` from `manifest.GenerateProviders`, importing each package. The
  built-in registry's is empty. The image label `io.linea.providers` names the
  providers.
- The worker calls each function once at start (`runtime.Plugins`) and refuses
  to start on an empty or duplicate name. Its hello carries `providers` (name,
  package, component types).
- Reports carry `runtime.providers`; a simulated endpoint a provider served
  names it (`simulated_endpoints[].provider`) and the run's `mocks`
  declarations name the provider with what it reported. Runtime listings (CLI,
  HTTP, MCP, web) list the providers, and composing a manifest from sources
  names the providers found.
